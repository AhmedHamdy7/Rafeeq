## ✅ Backend answered: TRIPS-16 Demand response documented + rule keys confirmed (B-16)

**Merged to `main`** in `daaa3ec`. 📝 Docs only; the API didn't change. Guide §4.6 → `GET / POST / PATCH / DELETE /commute-demands/{demand}` now shows the full response with an example.

### The response (`POST`, `GET`, `PATCH` all return it)
`id`, `status`, `origin {lat, lng, label, placeId}`, `destination {…}`, `commuteType`, `daysMask`, `arrivalWindowStart`, `arrivalWindowEnd`, `flexibilityMinutes`, `maxWalkMinutes`, `maxDetourMinutes`, `audiencePreference`, `womenOnly`, `rules[]`, `tier`, `matchCount`, `wantsReturnTrip`, `expiresAt`, `createdAt`.

### Answers to the question
| You asked about | Answer |
|---|---|
| `arrivalTime` | **There's no single field.** The arrival is the window `arrivalWindowStart`–`arrivalWindowEnd` (`HH:MM:SS`), bent by `flexibilityMinutes` |
| `paused` | **Not in the response.** A paused demand reads `status: "PAUSED"`. `paused` is only sent in the `PATCH` body |
| `audiencePreference` | `women_only` · `any_verified` |
| Rule keys | ✅ **Non-smoking → `nonsmoking`, Quiet → `quiet`, A/C → `ac`**. Also accepted: `nofood`, `luggage`, `front` |
