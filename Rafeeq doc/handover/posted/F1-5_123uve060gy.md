**Built (AUTH-07, AUTH-08, D-0022):**
- Code lifetime **300 s** (was 120), **3** wrong tries (was 5), then the **number** is locked for **5 minutes** for that purpose. The lock covers every challenge, so asking for a new code no longer resets the guessing.
- While locked, both `POST /auth/otp/request` and `POST /auth/otp/verify` answer **`429 AUTH_OTP_LOCKED`** with `Retry-After` and `error.fields.lockedUntil`:
```json
{ "success": false, "error": { "code": "AUTH_OTP_LOCKED",
  "message": "Too many incorrect codes. You can try again in a few minutes.",
  "fields": { "lockedUntil": ["2026-11-01T18:05:00Z"] } } }
```
- All three are admin settings: `auth.otp.ttl_seconds`, `auth.otp.max_attempts`, new `auth.otp.lock_seconds`. The lock is stored on the challenge row (`locked_until`) and logged as the `otp_locked` security event.
- `AUTH_OTP_MAX_ATTEMPTS` now only means the per-minute rate limit.
